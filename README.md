# 山东科技大学第二课堂自动抢报工具
> 脚本版本：v0.2.6

## 工具简介
本工具用于自动报名**第二课堂信息化管理系统**里的活动。通过 WebVPN 访问校园二课系统，实时抓取活动列表，可以在报名开始时准点自动抢报；对于已满员的活动，支持蹲守模式，一旦有人退报释放名额就立刻补位。

## 环境要求
1. 操作系统：Windows（脚本使用 Edge 浏览器登录，基于 tkinter 图形界面）
2. 建议 Python 3.8 及以上 3.12 及以下版本（开发环境为 3.12）
3. 安装第三方依赖库
```bash
pip install requests selenium
```
4. 本机安装 Microsoft Edge 浏览器；Edge 驱动由 selenium 自动管理，首次运行自动下载匹配驱动
5. 拥有学校 WebVPN 账号（学号 + 密码）

> 说明：
> - `cred.json`：保存 Authorization（令牌）和 Cookie。登录失效脚本会自动重新登录；凭证为明文存储，请勿转发给他人。
> - `task.json`：保存抢报队列任务，程序重启自动恢复；报名截止的过期任务会自动清理。
> - `task.tmp.json`：写入任务时的临时文件，用于原子替换 `task.json`，无需理会。

双击 `launcher.exe` 启动程序。

## 首次登录（WebVPN 抓取令牌）
第一次运行脚本会自动打开 Edge 浏览器，请按下面步骤操作：
1. 在弹出浏览器窗口登录 `webvpn.sdust.edu.cn`，输入学号密码完成 WebVPN 登录
2. 在 WebVPN 主页手动点击【第二课堂信息化管理系统】，会新开标签页
3. 确认新标签页成功进入二课首页（地址栏以 `#/home` 结尾）
4. 回到脚本弹窗，点击【确定】

脚本自动执行操作：
- 解析 WebVPN 代理地址
- 注入代码监听网络请求，抓取接口 Authorization 令牌
- 将凭证写入 `cred.json`，提示 `凭证&VPN代理地址已保存`

### 自动抓取令牌失败
日志提示`自动抓取超时`时，手动复制令牌：
1. 保持停留在二课系统页面，按 `F12` 打开开发者工具
2. 切换到【网络(Network)】标签，刷新页面
3. 点开任意一条 `list?` 开头的请求
4. 在【请求头(Request Headers)】找到 `Authorization`
5. 完整复制该串内容，粘贴到脚本输入框，点击确定

### 令牌复用机制
- 脚本默认复用上次保存的 Authorization，仅刷新 Cookie，减少重复登录
- 连续 3 次复用失败，自动清空缓存，强制完整登录流程

### 登录失效自动重登（v0.2.6）
- 报名接口或活动详情接口返回 `code:10001`（`登陆失败，请重新登陆`）时，脚本会置位重登标记
- 后台主循环只发起**一次**浏览器重新登录，完成后刷新全局请求头，所有盯防线程自动使用新凭证
- 重登失败时 30 秒后重试，不会让所有线程各自弹浏览器窗口
- 重登期间日志会提示 `🔑 检测到登录失效，开始重新登录`，按首次登录流程完成操作即可

## 界面操作说明
### 筛选设置区
> 修改参数自动刷新，无需额外点击按钮
- **抓取天数**：抓取未来多少天的活动，默认 7 天，上限 30 天
- **学院筛选**：按学院过滤；选择全部代表不限学院，不限学院的活动始终展示
- **活动类型**：二课五大分类筛选
  - 思想政治与道德修养
  - 社会实践与志愿服务
  - 文化艺术与身心发展
  - 学术科技与创新创业
  - 社会工作与技能拓展

### 操作按钮
1. **刷新活动列表**：按照当前筛选条件，重新抓取活动数据
2. **加入队列**：输入活动序号（界面左侧显示的序号，从 1 开始），多个序号用空格分隔，点击加入
3. **删除队列**：输入队列列表中的任务序号（从 1 开始），点击删除

> 序号以**当前筛选后界面显示的列表**为准，不会因为筛选而错位；如果活动列表已刷新导致该 ID 不在当前列表中，会提示重新加入。

### 左侧：可报名活动列表
活动展示示例（序号从 1 开始）：
```
[1] 🟢可报 ⚠名额已满 活动名称
    名额：23/50 | 限院:某某学院 | 免审 | 无作业
    类型：社会实践与志愿服务 | 学分：1.0 | 地点：...
    承办：...组织
    报名：11-06 12:00 ~ 11-07 23:59
    活动：11-08 14:00 ~ 11-08 17:00
```

状态标记含义：
| 标记 | 含义 |
|------|------|
| 🟢可报 | 报名通道已开放，可直接抢报 |
| 🟡倒计时 | 报名尚未开始，等待倒计时准点抢报 |
| ⚪未开 | 暂无报名时间信息 |
| ⛔已截止 | 报名时间已结束，无法加入队列 |
| ⚠名额已满 | 活动人满，加入队列自动转为蹲守任务 |
| [队列] | 该活动已经存在于抢报队列 |

### 右侧：已加入抢报队列
格式示例（序号从 1 开始）：
```
序号 | 类型 | 活动名称
[1] [普通]  某某活动
[2] [蹲守]  某某已满活动
```
- `[普通]`：到时间准点抢报
- `[蹲守]`：活动已满，循环轮询名额，释放后立即报名

## 两种抢报模式

### 普通抢报（normal）
1. 未开始报名的活动加入队列，脚本会在报名开始前约 **0.45 秒**发起报名
2. 失败自动重试，最多 15 次；失败间隔逐步增大（退避策略）
3. 报名成功弹出提示框，任务自动从队列移除
4. 遇到登录失效（`code:10001`）**不计入重试次数**，等自动重登完成后继续抢

### 蹲守抢报（watchdog）
1. 人数已满（`enrollCount ≥ peopleLimit`）的活动加入队列时自动转为蹲守任务
2. **名额数据来源**：活动列表接口快照（与界面显示、加入队列判断同源），随后台主循环约每 4 秒刷新一次；活动详情接口**不返回**人数上限与已报人数，因此不再用它判定
3. **二次确认**：连续两轮都检测到“已报人数 < 人数上限”才真正发起报名，单次脏数据不会误报
4. 以下情况一律**不判定名额、不发起报名**（宁可不报，也不误报）：
   - 列表未返回有效的 `peopleLimit / enrollCount`
   - 列表标记 `isAbleEnroll = 0`（当前不可报名）
   - 快照超过 `SNAPSHOT_STALE_SEC`（默认 30 秒）未更新
   - 活动已从当前抓取范围内消失
5. 每约 0.8 秒做一轮检查；发起报名失败后退避 2.5 秒以上再判定
6. 最大轮询 1200 轮（约 16 分钟）；达到上限未抢到则弹窗提示，任务自动停止
7. 名额被抢走 / 接口拒绝时不会刷屏，只在退避后重新判定

## 日志窗口
- 可设置`最大日志条数`、`刷新间隔(ms)`，修改完成点击【应用】生效
  - 日志条数必须大于0；刷新间隔最小20ms
- 日志输出内容：
  - 活动抓取、学院加载、服务器时间校准信息
  - 抢报倒计时（剩余小于30秒才输出日志，平时静默）
  - 报名成功/失败、蹲守二次确认与名额释放
  - 凭证失效、限流429休眠、异常重试信息

## 常见问题 FAQ

**Q1：登录提示自动抓取Authorization超时怎么办？**
> 参考文档中手动复制令牌的操作步骤，手动粘贴令牌即可。

**Q2：运行提示找不到模块 requests / selenium**
> 在终端执行：`pip install requests selenium`，安装依赖库。

**Q3：日志提示凭证失效 / 需要重新登录**
> Authorization 或者 WebVPN 票据过期，脚本会自动打开浏览器，按照首次登录流程重新操作。v0.2.6 起整次重登只触发一次，完成后所有盯防线程自动恢复。

**Q4：日志出现 `⚠️【报名失败】... code:10001 msg:登陆失败，请重新登陆`**
> 说明 Authorization 已过期。v0.2.6 不会再每 0.8 秒重复刷这条日志：脚本会请求一次重新登录，完成后继续蹲守。若反复出现，请检查弹出的浏览器窗口是否完成了 WebVPN 登录。

**Q5：活动明明已经满员，旧版本为什么还一直提示“检测到释放名额”？**
> v0.2.5 及之前从活动详情接口读取已报人数，而该接口并不返回该字段，读到的值恒为 0，于是“0 < 人数上限”永远成立。v0.2.6 已改用活动列表快照判定，并加了二次确认，不会再误报。

**Q6：部分活动显示 ⚠名额已满**
> 程序设计如此，不会隐藏满员活动，可以加入蹲守队列等待他人退报。

**Q7：抢报失败是否会无限重试？**
> 普通抢报最多重试 15 次；蹲守模式最多轮询 1200 轮，到达上限自动停止任务，不会无限运行。

**Q8：程序被强制关闭、断电，任务会丢失吗？**
> 任务定期保存至`task.json`（每 5 轮主循环一次 + 每次队列变更即时保存），重启程序自动恢复；已经截止的过期任务会自动清理。

**Q9：抓取活动时间偶尔不准确？**
> 脚本会自动计算服务器与本机的时间偏移，修正时间，降低本地时钟不准带来的影响。

**Q10：蹲守检测为什么会比 0.8 秒慢一点？**
> v0.2.6 的名额判定跟随活动列表刷新节奏（约 4 秒一轮），换来的是不再误报、不再空转报名。若同时有人在抢，网络与系统本身也有延迟，请以网页实际结果为准。

## 脚本自定义配置
> 使用记事本打开 `app/山科第二课堂.pyw`，修改脚本顶部配置区，保存后重启程序生效。
> ⚠随意修改参数可能造成程序异常。

```python
FETCH_DAY_MAX        = 30    # 抓取天数最大上限
FETCH_DAY_DEFAULT    = 7     # 默认抓取天数
MAX_WORKER           = 6     # 同时运行的抢报线程数上限
SIGN_MAX_RETRY       = 15    # 普通抢报最大重试次数
SPRINT_ADVANCE_MS    = 450   # 报名开始提前量（毫秒）
SPRINT_SLEEP         = 0.18  # 冲刺阶段轮询间隔（秒）
WATCHDOG_INTERVAL    = 0.8   # 蹲守轮询间隔（秒）
WATCHDOG_MAX_RETRY   = 1200  # 蹲守最大轮询轮数
SNAPSHOT_STALE_SEC   = 30    # 列表快照超过该秒数视为过期，蹲守不做名额判定
LOOP_SLEEP           = 4     # 后台主循环间隔（秒），也是列表快照刷新节奏
DETAIL_RETRY         = 2     # 获取活动详情接口最大重试次数
TASK_SAVE_INTERVAL   = 5     # 后台循环多少轮自动保存一次任务
CACHE_TTL            = 60    # 活动详情缓存有效期（秒）
BASE_BACKOFF         = 0.15  # 报名失败退避起始时间（秒）
MAX_BACKOFF          = 2.0   # 报名失败退避上限（秒）
QUIET_COUNTDOWN      = True  # 长倒计时是否静默（False=一直打印倒计时）
COUNTDOWN_ALERT_SEC  = 30    # 剩余小于该秒数才开始打印倒计时
FILTER_FULL          = False # False=人满活动也显示在界面（不建议改）
MAX_LOG_ITEMS        = 150   # 日志最大行数
LOG_POLL_INTERVAL    = 120   # 日志刷新间隔(ms)
STABLE_AUTH_MAX_CONTINUE_FAIL = 3  # 复用 Authorization 连续失败阈值
# LOG_X/LOG_Y 等参数：日志窗口、活动窗口位置大小、置顶设置
```

> 调参建议：把 `WATCHDOG_INTERVAL` 调小不会加快名额判定（判定依赖列表快照）；想更灵敏请改小 `LOOP_SLEEP`，但同时会增加接口访问量，注意被限流（429）。
